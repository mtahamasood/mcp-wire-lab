# Learner walk: lessons 02 to 04

A newcomer's walk (knows JSON, a terminal and Python; nothing of JSON-RPC or MCP) from the
README through lessons 02, 03 and 04, on a fresh clone. Node was already at 24.22.0, so no
`nvm` step was needed.

## Part A: clean-clone walk

The command from the task, `git clone --recurse-submodules <repo>`, checks out the repository's
default branch, which is `phase-01-wire-tap`, not `main`. That branch holds only lesson 01 and
a `record.sh` with no `--client` option, so step 4 fails there (finding 1). The walk was
therefore run twice: once on the default branch exactly as the task states, once on `main`
(`git clone -b main --recurse-submodules ...`), which is where lessons 02 to 04 live.

Clone of the default branch (as written):

| Step | Exit code | Wall time | Note |
| --- | --- | --- | --- |
| 1. clone with submodules | 0 | 18 s | Lands on `phase-01-wire-tap`; only lesson 01 present |
| 2. `scripts/bootstrap.sh` | 0 | 8 s | `npm audit` notice (README warns of it); a `core.hooksPath` warning about the pre-push hook (finding 12) |
| 3. `scripts/gate.sh` | 0 | 27 s | "gate: all green", lessons: 1 checked |
| 4. `scripts/record.sh --client tour walk` | **1** | 0 s | "record: no such fixture: --client"; there is no `tap.show` command to run |
| 5. `git status --porcelain` | 0 | 0 s | Empty |

Clone of `main`:

| Step | Exit code | Wall time | Note |
| --- | --- | --- | --- |
| 1. clone with submodules | 0 | 25 s | |
| 2. `scripts/bootstrap.sh` | 0 | 10 s | Same two notices as above |
| 3. `scripts/gate.sh` | 0 | 113 s | "gate: all green", lessons: 4 checked; the README does not say the gate takes about two minutes |
| 4. `scripts/record.sh --client tour walk`, then the printed `tap.show` command | 0 and 0 | 2 s and under 1 s | Prints `recorded:` and `read it:` lines; the trace shows the handshake and 17 requests |

Result: Part A passes on `main` (about 2.5 minutes in total, gate dominating) and fails at step 4
on the default branch.

## Part B: learner walk findings

Every runnable block in lessons 02, 03 and 04 was run and printed what its `expect` block says.
Every citation I followed (spec and server lines, `client/` function names) pointed where it
claimed. The findings below are about the path to the lessons and about what a learner cannot
answer or reproduce from the text.

1. **README / Set up (all three lessons): wrong, severity stall.** Following the README's own
   clone command lands on the `phase-01-wire-tap` branch. The README there lists only lesson 1,
   and the `--client` option every later lesson relies on fails with "no such fixture:
   --client". A learner never reaches lesson 02 and cannot tell why. Suggested fix: make `main`
   the default branch, or add `git checkout main` / `git clone -b main` to the Set up block and
   say which branch a learner should be on.

2. **Lesson 04 / Experiments, fault run, `--delay` paragraph: wrong, severity wrong.** It says
   to "read the latency `tap.show` prints for each reply; which part of a delayed run is the tap
   and which is the server?". With `--delay s2c:2000` the printed reply latencies stay small
   (about 264 ms for `initialize`, then 38 ms and 1.4 ms), because the delay is applied after the
   reply is recorded. The 2 s appears instead as a jump in the timestamp of the next client
   frame, with a "tap fault" row after each reply. A learner who looks at the latencies finds
   no tap time at all and cannot answer the question. Suggested fix: say where the delay shows
   (the gaps between frames and the fault rows), or change what `tap.show` prints so latency
   includes the hold, and give the expected numbers.

3. **Lesson 04 / Experiments (the "other six"): unclear, severity stall.** The lesson names
   fixtures (`edge-missing-jsonrpc`, `exp-list-first`, `edge-duplicate-id`, ...), but
   `--explain ...#name` needs the walkthrough's section names (`missing-jsonrpc`,
   `before-initialize`, `duplicate-id`, ...). Trying `#exp-list-first` gives only "has no section
   `## exp-list-first`", without listing the valid names. The mapping table is in the
   walkthrough's opening, which the lesson does not point at. "Check yourself" question 2 then
   says `duplicate-id`, a third spelling. Suggested fix: in the lesson, list the pairs
   (fixture, `#name`) or link the walkthrough's table, use one spelling throughout, and have the
   error message list the valid section names.

4. **Lesson 04 / Experiments: `oversized-frame`: unclear, severity stall.** The lesson offers it
   as an experiment to "pick", but it has no fixture; it is "generated by `tests/test_e2e.py`".
   There is no command a learner can run to record it, and the walkthrough only has notes for a
   trace one cannot produce. Suggested fix: give the command that writes the fixture and records
   it, or drop it from the list of experiments a learner can pick.

5. **Lesson 03 / Check yourself question 4 and its answer: unclear, severity unclear.** The
   question is two questions glued together ("answers -32601 ... What does it answer, and what
   does the spec say, for an elicitation mode it did not declare?"). The answer cites the
   elicitation page for `-32602` but then says other capabilities get `-32601` "as the roots
   page says" with no citation (the rule is at the roots page, around line 144: "Client does not
   support roots: `-32601`"). Suggested fix: split into two questions and cite the roots line in
   the same `spec:path:line "fragment"` form as the rest.

6. **Lessons 02 and 03 / Predict: unclear, severity unclear.** Several Predict items are never
   answered in a place a learner can check. Lesson 03 Predict 1 (what changes in the tool list)
   is only implied by the `matrix` table; Predict 2 (how many messages carry `"id": 0`; I count
   four: the client's `initialize`, its reply, the server's first `roots/list`, and the client's
   answer) and Predict 4 (what a client that declared nothing should answer) are not answered.
   Lesson 02 Predict 2 (which messages the server sends unasked) is answered only inside the
   walkthrough notes. Suggested fix: add a one-line answer to each Predict item in the existing
   "Answers" block, or say that the walkthrough answers them and where.

7. **Lesson 03 / Run, `matrix`: unclear, severity unclear.** The `expect` block shows one row of
   the table. The learner gets a six-row table with a third column, "server-initiated methods
   seen", that the lesson never explains, and the pattern (only some rows list `roots/list` or
   `notifications/message`) is exactly what Predict 1 asks about. Suggested fix: a sentence on
   how to read the three columns and which row to compare with lesson 02's 16 tools (the server
   tour re-lists 21 tools once everything is declared).

8. **Lesson 02 / Experiments item 3: unclear, severity unclear.** "change the `message` the tour
   sends to `echo`, and the text the tour expects back" reads as if the new value were the word
   `echo`. The edit is two lines in `client/tour.py` (the `"hello"` argument and the
   `"Echo: hello"` check); a learner has to hunt for them. It also leaves the tracked file
   modified, which the gate then sees. Suggested fix: name the two lines, give an example value,
   and end with `git checkout client/tour.py`. (Lesson 03 item 3, `OTHER_ROOT`, has the same
   missing revert instruction.)

9. **Lesson 02 / Run: nit.** The direct `python3 -m client tour` output numbers its steps 0 to 17
   (18 lines, step 1 being the `initialized` notification), while the lesson and trace talk about
   17 requests with ids 0 to 16. Step numbers and ids differ by one from step 2 on, which is
   confusing in a lesson about ids. Suggested fix: one sentence saying the step numbers are the
   tour's own and not request ids.

10. **Lesson 02 / Experiments intro: unclear, severity unclear.** "Manual mode ... sends exactly
    the lines you type" and "type messages by hand", but every experiment pipes `printf`. The
    lesson never says how to use it interactively or how to end the session (I did not test the
    interactive case). Suggested fix: one example of an interactive session and how to quit.

11. **Lesson 04 / Run (batch): nit.** "`scripts/record.sh` may also print that the run ended with
    exit code 1": it did so on every run, on stderr, so the lesson's `sed` capture does not
    see it. Say "will print", and where.

12. **README / Set up: nit.** Bootstrap prints a warning that `core.hooksPath` is set so git may
    not run the repo's pre-push hook. The README promises a pre-push hook that refuses
    to publish run output but says nothing about this warning. Suggested fix: one line on what
    the warning means for a learner who is not pushing.

13. **README / How it is checked: nit.** `scripts/gate.sh` took about two minutes on `main`
    (27 s on the first-phase branch). Say so, so a learner does not think it hung.
